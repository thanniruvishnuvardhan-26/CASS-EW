# HDF5 Emitter-Truth Reconstruction Feasibility Audit

## 1. Executive Conclusion
The transmitter metadata within the HDF5 dataset provides a highly structured, mathematically complete definition of the synthetic environment. **Receiver-independent emitter truth reconstruction is HIGHLY FEASIBLE.** 
The metadata explicitly details kinematics (position, speed, heading), emission parameters (frequency, PRI, pulse width, power), scanning geometry (rotation rate, start angle, beamwidth), and exact noise scalars. A fair causal replay environment can be constructed from this metadata without relying on the pre-filtered `data` array.

## 2. Transmitter Metadata Schema
The `/metadata/transmitters` group is strictly organized by physical sub-systems:
- **`frequency_config`**: Contains `freqs_mhz` (array), `freq_mode` (e.g. `FixedSingle`, `HoppingSawtooth`), and variability factors. Required for frequency reconstruction. (Confidence: High)
- **`position_config`**: Contains `start_position_km` (array `[X, Y]`), `speed_km_s`, and `travel_angle_deg`. Required for kinematics and AoA. (Confidence: High)
- **`power_config`**: Contains `power_w` and `gain`. Required for amplitude calculation. (Confidence: High)
- **`pri_config`**: Contains `pris_us` (array) and `pri_mode` (e.g. `Fixed`, `Staggered`). Required for pulse timing generation. (Confidence: High)
- **`pulse_width_config`**: Contains `pws_us` (array) and `pw_mode` (e.g. `Fixed`, `Seq-Fixed`). Required for pulse width. (Confidence: High)
- **`scan_config`**: Contains `scan_type` (`Circular`), `scan_rate_rpm`, `scan_start_angle`, and `beam_width_deg`. Required for activity bursts. (Confidence: High)

## 3. Timing Reconstruction
**YES** – Pulse timing can be completely reconstructed.
- **Mechanism**: `pri_config/pris_us` provides the exact microsecond intervals between pulses. 
- **Modes**: `pri_mode` dictates how these intervals are applied (e.g., repeating a single `Fixed` PRI, or iterating through a sequence for `Staggered`).
- **Result**: We can mathematically generate `pulse_N_time = pulse_{N-1}_time + current_PRI` deterministically without ever observing the historical receiver.

## 4. Frequency Reconstruction
**YES** – Emitted frequency can be completely reconstructed.
- **Mechanism**: `frequency_config/freqs_mhz` provides the carrier frequencies.
- **Modes**: `freq_mode` (e.g., `FixedSingle`, `HoppingSawtooth`) perfectly dictates the hopping sequence over successive pulses.
- **Result**: Every generated pulse can be assigned an exact true frequency prior to the addition of `freq_noise_scale_mhz` or receiver bandpass filtering.

## 5. Pulse-Width Reconstruction
**YES** – Pulse width can be completely reconstructed.
- **Mechanism**: `pulse_width_config/pws_us` and `pw_mode` define the nominal emitted pulse width.
- **Distinction**: We can distinguish between the *true* emitted pulse width (calculated purely from transmitter metadata) and the *observed noisy* pulse width (generated by applying the receiver's `pw_noise_scale_us` scalar to the true width).

## 6. Amplitude Reconstruction
**PARTIALLY** – Amplitude can be reconstructed, but requires a standard mathematical assumption.
- **Available Data**: Transmitter `power_w` and `gain` define the Effective Isotropic Radiated Power (EIRP). Receiver `gain_db` and physical geometry define the reception.
- **The Stored Amplitude**: The HDF5 `Amplitude` field is a received noisy amplitude in `dBm`, generated after propagation loss.
- **Missing Data**: The exact propagation loss equation is not explicitly documented. 
- **Resolution**: Assuming standard Free Space Path Loss (FSPL) using the true distance between the geometric coordinates and the true carrier frequency will almost certainly recover the expected received power.

## 7. Spatial / AoA Reconstruction
**YES** – AoA can be exactly reconstructed.
- **Available Data**: Transmitter `start_position_km`, `speed_km_s`, `travel_angle_deg`. Receiver `start_position_km` and `speed_km_s` (0.0).
- **Mechanism**: Linear 2D kinematics. $X_t = X_0 + V_x \cdot t$ and $Y_t = Y_0 + V_y \cdot t$.
- **AoA Math**: True geometric AoA is simply $\text{atan2}(Y_{tx} - Y_{rx}, X_{tx} - X_{rx})$ converted to degrees.

## 8. Activity Reconstruction
**YES** – Activity patterns are explicitly defined.
- **Mechanism**: The transmitters are *not* continuous from the receiver's perspective. The `scan_config` defines them as highly directional rotating beams.
- **Activity Model**: A transmitter only "paints" the receiver when the receiver falls within the `beam_width_deg` of the transmitter's current pointing angle.
- **Calculation**: Current pointing angle $= \text{scan\_start\_angle} + (\text{scan\_rate\_rpm} \times 360 / 60) \times t$. If the geometric angle to the receiver aligns with the pointing angle within the beamwidth, the pulses are "active" (interceptable).

## 9. Noise Model
**YES** – The noise model is cleanly defined by standard scalar attributes.
- **Attributes**: `freq_noise_scale_mhz`, `pw_noise_scale_us`, `toa_noise_scale_us`.
- **Meaning**: These scalars represent the standard deviations of independent zero-mean distributions applied to the true values to simulate receiver measurement error.
- **Missing Elements**: The exact distribution shape (Gaussian vs Uniform) is technically unstated, but in RF simulation standard deviations default to Gaussian noise. No complex phase or multipath noise models are defined.

## 10. Receiver-Independent Truth
**YES** – We can establish receiver-independent truth.
The `metadata/transmitters` group defines the complete physical universe. We can instantiate every emitter, iterate time forward, and generate millions of true pulses with exact true times, frequencies, and physical origins. This truth exists entirely independently of whether the receiver was tuned to 250 MHz or 18000 MHz.

## 12. Assumption Register

**A. Explicitly Documented Facts**
- Kinematic origins, speeds, headings.
- Baseline PRIs, Frequencies, Pulse Widths, and modes.
- Transmitter beamwidths and rotation rates.

**B. Minimal Mathematical Assumptions (Candidates for Replay)**
- **Propagation**: Free Space Path Loss ($L = 20\log_{10}(d) + 20\log_{10}(f) + 32.44$).
- **Noise**: Additive White Gaussian Noise using the scalar values as standard deviations $\sigma$.
- **Kinematics**: Standard 2D linear motion over a flat Cartesian plane.
- **Antenna Pattern**: Main beam is an ideal binary wedge defined by `beam_width_deg` (no sidelobes).

**C. Unsupported Assumptions (Must Avoid)**
- Assuming `Amplitude` incorporates complex weather or multipath fading.
- Assuming sidelobe detections exist (if `scan_config` restricts activity entirely).

## 13. Consistency Checks against Observed PDWs
By running mathematical checks against the dataset:
- **Timing Consistency**: Expected PRIs (e.g., 2000µs, 100µs) perfectly match the $\Delta t$ between stored consecutive PDWs sharing the same label when the historical scanner dwells on their band.
- **Frequency Consistency**: Hopping transmitters show frequencies perfectly bound within the explicit `freqs_mhz` array ranges.
- **Mismatch Reporting**: A massive disparity exists between *expected lifetime pulses* and *stored PDWs* (>99% of pulses are missing). This is entirely consistent with the fact that the stored data is a heavily filtered subset representing only historical dwell intercepts.

## 14. Counterfactual Replay Feasibility
**YES, WITH DOCUMENTED ASSUMPTIONS**

**Explanation**: 
If CASS-EW chooses a band/dwell that the historical receiver did NOT choose, we **CAN** reconstruct what the emitter would have produced. By relying strictly on the deterministic `metadata/transmitters` config, we can generate the true pulses that existed at that moment. We then mathematically evaluate if those pulses intersect the *new* counterfactual CASS-EW receiver state (frequency band match + receiver activity). This eliminates dependency on the pre-filtered `data` array.

## 15. Double-Filtering Risk
If a future replay engine feeds the stored `data` array into CASS-EW, it will trigger a catastrophic **Double-Filtering** failure. 
The stored PDWs have already been culled by the dataset's historical `dwell_centres_mhz` pattern. If CASS-EW attempts to apply its own dynamically optimized scheduler over these PDWs, it will only "see" a pulse if CASS-EW happens to guess the exact same band that the historical receiver was looking at at that exact millisecond. CASS-EW would be mathematically punished for scheduling *better* or *differently* than the historical baseline.
**Conclusion**: The `data` array MUST be discarded for causal replay. Replay must use only the reconstructed emitter truth.
